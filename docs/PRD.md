# PRODUCT REQUIREMENTS DOCUMENT
# Mobeng Workshop CAD Designer
Version 1.0

## 1. Vision
Build a browser-based parametric workshop planning tool that produces accurate, measurable, CAD-like 2D automotive workshop layouts and can export them to PDF/DXF and, through a dedicated CAD conversion layer, DWG.

## 2. Problem
Generic image AI frequently creates visually attractive but geometrically impossible workshop layouts:
- incorrect dimensions,
- inconsistent bay sizes,
- blocked vehicle paths,
- impossible turning,
- equipment overlap,
- missing clearances,
- changing room counts,
- distorted proportions.

The product solves this by separating geometry from visualization.

## 3. Target users
- Mobeng PSD / Product & Service Development
- Workshop development team
- Operations
- Expansion / property team
- Designers
- Engineering / architecture partners
- Admin / standards owner

## 4. Product type
WEB APPLICATION.

Recommended stack:
- Next.js + TypeScript
- React
- SVG-based CAD editor
- Zustand or equivalent state management
- Local JSON/localStorage for prototype
- Backend later: InsForge or Supabase
- Dedicated export/conversion service for DXF/DWG

## 5. MVP objective
Given a site/building and workshop requirements, generate a valid parametric 2D layout, allow manual CAD-like editing, validate constraints, calculate score, and export a professional drawing.

## 6. Core workflows

### Workflow A — Create project
1. Create project
2. Select standard version
3. Enter site dimensions
4. Enter building dimensions
5. Define road/entrance/exit
6. Select services and quantities
7. Select equipment
8. Select vehicle class
9. Generate layouts

### Workflow B — Generate
1. Build boundary
2. Place fixed objects
3. Create zones
4. Place service bays
5. Place equipment
6. Calculate envelopes
7. Calculate circulation
8. Collision detection
9. Validate hard constraints
10. Generate alternatives
11. Score alternatives
12. Select recommended layout

### Workflow C — Edit
User can:
- select,
- move,
- copy,
- rotate,
- mirror,
- delete,
- insert blocks,
- draw walls,
- add doors/windows,
- add dimensions/text,
- measure,
- change properties.

Every modification triggers validation.

### Workflow D — Export
- SVG
- PNG
- PDF
- DXF
- DWG through a conversion service

## 7. Functional requirements

### FR-001 Project management
Create, duplicate, rename, archive projects.

### FR-002 Standards
Project must reference an immutable standard version.

### FR-003 Parametric geometry
Every object has coordinates, dimensions, rotation, layer, type, and metadata.

### FR-004 Units
Primary internal unit: meter.
Display precision configurable.

### FR-005 CAD editor
SVG canvas with pan, zoom, grid, snapping, selection and property editing.

### FR-006 Layers
Support visibility, locking and ordering.

### FR-007 Blocks
Reusable equipment, vehicle, door, window and structural blocks.

### FR-008 Dimensions
Dimensions must be linked to geometry and update when geometry changes.

### FR-009 Validation
Hard errors prevent approval; warnings can be accepted only with explicit action.

### FR-010 Collision
Detect object-object and envelope-envelope intersections.

### FR-011 Circulation
Validate vehicle entry, service access, exit, and required maneuvering space.

### FR-012 Scoring
Generate a weighted layout score from configurable criteria.

### FR-013 Alternatives
Generate multiple candidates and rank them.

### FR-014 Admin
Admin can edit parameters, rules, equipment, vehicle classes, services, zones, layers, blocks and scoring weights.

### FR-015 Versioning
Standards support draft, published, archived versions.

### FR-016 Audit
Changes to standards are logged.

### FR-017 AI assistant
Natural-language commands become proposed structured changes, validated before application.

### FR-018 Visualization
Approved geometry can be sent to an image/3D visualization workflow. Visualization cannot modify the source geometry.

## 8. Non-functional requirements
- Responsive desktop-first web UI
- Fast pan/zoom at typical workshop drawing sizes
- Deterministic geometry calculations
- Undo/redo
- Autosave locally in prototype
- No silent data mutation
- Clear validation explanations
- Exported PDF must preserve dimensions
- DXF must use correct units/layers
- DWG must be generated by a real CAD conversion process, not by renaming a file extension

## 9. Roles
SUPER_ADMIN:
all permissions.

ADMIN:
manage standards, equipment, rules, scoring, templates, blocks.

DESIGNER:
create/edit projects and layouts, generate, validate, export.

VIEWER:
view and export where permitted.

## 10. Acceptance criteria
A release is acceptable only if:
- geometry is deterministic,
- all dimensions originate from data,
- no hard constraint violation is accepted as valid,
- generated layout is editable,
- dimensions update after geometry changes,
- standards can be changed without source-code changes,
- old projects retain their referenced standard version,
- PDF output is to selected scale,
- DXF opens in a CAD application with expected units/layers,
- DWG is produced by an actual supported conversion pipeline.
